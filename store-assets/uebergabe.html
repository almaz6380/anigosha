Diese Übersicht fasst zusammen, was gebaut wurde, warum es so gebaut wurde und was noch offen ist.

Die App in einem Absatz

Anigosha ist ein Anime-Wissensquiz für iOS und Android (plus Web). Es gibt einen Solo-Modus mit zwölf Serien in drei Schwierigkeitsstufen, eine tägliche Challenge, die für alle Spieler identisch ist, und rundenbasierte Duelle nach dem Quizduell-Muster. Wo noch keine echten Gegner da sind, treten computergesteuerte an. Finanziert wird die App über Werbung; später soll es einen Kauf „Werbung entfernen" geben.

Auf dem zweiten MacBook einrichten

git clone https://github.com/almaz6380/anigosha.git
cd anigosha
npm install

Danach fehlen vier Dinge, die bewusst nicht im Repository liegen:

1. Die Datei .env — in zwei Stufen

Stufe A — entwickeln und lokal spielen. Nichts kopieren nötig:

npx vercel login && npx vercel link      # Projekt: anigosha
npx vercel env pull .env                 # holt URL + Anon-Key von Vercel

Damit läuft npm run dev vollständig — Anmeldung, Fragen, Duelle.

Stufe B — zusätzlich Testskripte und Migrationen. Dafür fehlen zwei geheime Schlüssel, die absichtlich nicht bei Vercel liegen:

SchlüsselWoher
SUPABASE_SERVICE_ROLE_KEY Supabase-Dashboard → Projekt anigosha → Project Settings → API → Abschnitt „service_role"
SUPABASE_ACCESS_TOKEN supabase.com/dashboard/account/tokens — dort neu erzeugen
Diese beiden nie per Mail oder Chat verschicken. Der Service-Role-Key umgeht sämtliche Zugriffsregeln und kann alle Spielstände lesen und ändern.
Deployen geht auch ganz ohne .env. Vercel baut mit seinen eigenen hinterlegten Werten — ein Push auf main genügt.

2. .claude/settings.local.json

Erlaubt Claude, Datenbank-Migrationen selbst einzuspielen. Der Pfad muss der des neuen Rechners sein:

{ "permissions": { "allow": ["Bash(node /PFAD/ZU/anigosha/tools/run-sql.mjs *)"] } }

3. Vercel (optional)

npx vercel login, dann npx vercel link → Projekt anigosha. Zum Deployen nicht nötig — ein Push auf main genügt.

4. Playwright (für visuelle Prüfungen)

npm i --no-save playwright && npx playwright install chromium
Vor jeder Sitzung git fetch. Vercel deployt bei jedem Push auf main automatisch. Wer auf einem alten Stand aufsetzt, rollt mit seinem Push die Live-Version zurück. Dasselbe Problem gab es schon bei RechtsKarten.

Entscheidungen, die man kennen muss

Der Name — vier Anläufe

VerworfenGrund
AniBrainanibrain.ai war vier Jahre ein bekannter Anime-Dienst; das „Ani"-Präfix ist im Store übersättigt
TamashiTAMASHII NATIONS ist die Anime-Marke von Bandai Spirits
KiokuMarkenregister: KIOKU STUDIO in Klasse 41, KIOKU in Klasse 9 — genau unsere Klassen
Animatch, Animind, Animia, Animora, Animazealle vergeben; Animaze sogar als Marke in Klasse 9 und 41
Die wichtigste Lehre des Projekts: Eine Websuche ersetzt keine Markenrecherche. Bei „Kioku" war die Websuche völlig sauber — das Register zeigte 812 Einträge, darunter drei in unseren Klassen. Jeder Namenskandidat gehört zuerst in TMview, Klassen 9 (Software) und 41 (Spiele).

Keine Bilder von Anime-Figuren

Feste Entscheidung: keine erkennbaren geschützten Figuren, auch keine KI-generierten. Solche Bilder wären abgeleitete Werke — das Risiko trifft nicht nur diese App, sondern das ganze Entwicklerkonto samt MyPeak und WELLbooked. Stattdessen Textwissen (Fakten sind frei) und später verfremdete Bilderrätsel.

Lösungen verlassen nie den Server

Die Fragen-Tabelle ist für Clients komplett gesperrt. Die richtige Antwort kommt erst zurück, nachdem geantwortet wurde, und nur die erste Antwort zählt. XP und Elo werden ausschließlich serverseitig vergeben; ein direkter Schreibversuch prallt ab. Auch der 50:50-Joker rechnet auf dem Server, weil der Browser die Lösung gar nicht kennt.

Bots ziehen ohne Zeitsteuerung

Statt eines Cron-Dienstes ziehen die Bots beim nächsten Zugriff des Gegners — ihre Wartezeit halten sie trotzdem ein. Das spart eine komplette Infrastruktur, die stillschweigend ausfallen kann. (Genau das war bei WELLbooked passiert: Crons, die monatelang tot waren.)

Arbeitsweise, die sich bewährt hat

Migrationen immer erst trocken

Jede Datenbankänderung läuft zuerst in einer Transaktion, die zurückgerollt wird:

{ echo "begin;"; cat migration.sql; echo "rollback;"; } > dry.sql
node tools/run-sql.mjs dry.sql

Das hat mehrfach Fehler abgefangen, bevor sie die Produktivdatenbank erreichten — etwa eine Unterabfrage in einer CHECK-Bedingung und eine Fensterfunktion in einer Aggregation.

Zwei Fehler fielen ausschließlich im Screenshot auf: Die Wolken waren im ersten Entwurf unsichtbar (zu stark weichgezeichnet), und der Schleier beim Levelaufstieg war zu dünn. Ein dritter Fehler — der schwarze Balken über dem Himmel — war selbst im Screenshot unsichtbar, weil die Statusleiste zu iOS gehört und nicht zur Seite. Manche Fehler kann nur ein Blick aufs echte Gerät zeigen.

Was noch offen ist

Vor der Veröffentlichung zwingend

  1. Markenrecherche „Anigosha" in TMview, EUIPO und DPMA (Klassen 9 und 41) — war bei der Vorprüfung frei, sollte vor dem Launch bestätigt werden
  2. USE_TEST_ADS auf false in src/lib/ads.ts — erst unmittelbar vor dem Release-Build. Eigene Live-Anzeigen anzusehen kann das AdMob-Konto sperren, an dem auch MyPeak hängt
  3. DSGVO-Einwilligungsnachricht in AdMob erstellen und veröffentlichen
  4. E-Mail anigosha@wellbooked.at einrichten — sie steht im Impressum, du musst darüber erreichbar sein
  5. Rechtstexte prüfen lassen — sind sorgfältige Entwürfe, keine Rechtsberatung. Die WKO-Rechtsberatung ist für Mitglieder kostenlos

Danach

  • Firebase + Push („Du bist dran!" bei Duellen) — braucht ein Firebase-Projekt und für iOS einen APNs-Schlüssel aus dem Apple-Konto
  • RevenueCat für „Werbung entfernen" — setzt Store-Einträge voraus
  • Store-Einträge in App Store Connect und Play Console, App-Icon, Screenshots
  • Offene Designfrage: Duelle vergeben derzeit kein XP, nur Elo. Ein Levelaufstieg ist nur über Solo-Runden möglich. Das wirkt schief, sobald jemand überwiegend duelliert
